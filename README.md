# B2B 업무 트래커

팀의 루틴 업무와 프로젝트를 한 화면에서 관리하는 단일 HTML 앱입니다.
설치도, 서버도 필요 없습니다. 브라우저에서 열면 바로 씁니다.

## 바로 사용하기

**[업무 트래커 열기](https://hansol941201.github.io/task-tracker/)**

## 화면 구성

| 탭 | 용도 |
| --- | --- |
| 📅 오늘 | 팀 멤버별 오늘 할 일 — 루틴 체크와 진행중 프로젝트를 카드로 |
| 👥 팀별 보기 | 팀 단위로 묶어서 보기 |
| 🚀 자동화 | 팀에서 만든 자동화·대시보드 앱 모음 |
| 📖 매뉴얼 | 담당자별 업무 매뉴얼 |
| ⚙️ 관리 | 팀·멤버·루틴·업무 등록과 데이터 백업 |

## 업무의 두 종류

- **🔄 루틴 업무** — 매일·매주·매월·분기·매년 반복. 주기 안에서 한 번
  체크하면 그 주기는 완료로 처리되고, 다음 주기가 시작되면 자동으로
  미완료로 돌아갑니다.
- **🚀 프로젝트 / 🔁 루틴성 업무** — 일회성 작업. 프로젝트는 보조 업무로
  쪼갤 수 있고, 보조 업무 진척률의 평균이 메인 진척률에 자동 반영됩니다.

상태는 카드를 눌러 `할 일 → 진행 중 → 보류 → 완료` 순으로 순환합니다.
완료하면 진척률이 100%가 되고 완료일이 기록되며, 한 번 더 누르면 취소됩니다.

## 데이터 저장

브라우저 `localStorage` 의 `task_tracker_v19` 키에 JSON으로 저장합니다.

- 추가·수정·삭제하는 즉시 저장됩니다
- 새로고침하거나 브라우저를 껐다 켜도 그대로 유지됩니다
- 깃허브 동기화를 켜지 않으면 아무 데도 보내지 않습니다

### 백업과 이동

상단 **내보내기** 로 JSON 파일을 받고, **가져오기** 로 되돌립니다.
PC를 옮기거나 브라우저를 바꿀 때 이 파일 하나면 됩니다.

### 여럿이 함께 쓰기 — Firebase 실시간 공동 저장

팀 전원이 같은 데이터를 봅니다. 따로 설정할 것도, 로그인할 것도 없습니다.

- **화면에 보이는 내용의 출처는 언제나 Firebase 하나뿐입니다.**
  접속하면 먼저 팀 데이터를 다 읽고, 그다음에 화면을 그립니다.
  읽기가 끝나기 전에는 아무것도 그리지 않고, 아무것도 올리지 않습니다.
- 이 PC의 저장분은 **연결이 끊겼을 때만 쓰는 사본**입니다.
  팀 데이터가 있으면 이 PC의 내용과 섞지 않습니다 — 그래서 브라우저마다 화면이 달라지지 않습니다.
- 업무를 추가·수정·삭제하거나 루틴을 체크하면 곧바로 팀 데이터에 올라갑니다
- 다른 팀원의 변경은 실시간으로 화면에 들어옵니다
- 새로고침하면 항상 팀의 최신 데이터가 표시됩니다
- 인터넷이 끊기면 이 PC에 저장해 두었다가, 연결이 돌아오면 다시 올립니다

상단 배지가 현재 상태를 보여줍니다 — **연결 중** · **팀 데이터 동기화** · **저장 실패** · **연결 오류**.
배지를 누르면 연결 방식과 마지막 동기화 시각을 볼 수 있습니다.

| 항목 | 값 |
| --- | --- |
| Realtime Database | `b2b-task-tracker-39144-default-rtdb.asia-southeast1` |
| 공용 데이터 경로 | `shared/taskTracker` |
| 연결 방식 | Firebase Web SDK 실시간 리스너 (막히면 2초 주기 동기화로 자동 전환) |

### 멤버는 고정된 세 명입니다

같은 사람의 카드가 두 장씩 생기던 문제를 막기 위해 멤버 id 를 고정했습니다.

| 이름 | id | 순서 |
| --- | --- | --- |
| 조재연 | `member_jo_jaeyeon` | 1 |
| 최세혁 | `member_choi_sehyeok` | 2 |
| 신한솔 | `member_shin_hansol` | 3 |

접속했을 때 예전 형식의 멤버가 남아 있으면 **한 번만** 정리합니다.

1. 손대기 전에 원격 전체를 `backups/<시각>` 에 그대로 복사합니다.
2. 중복 멤버에 걸려 있던 업무·루틴·대시보드·매뉴얼의 담당자를 대표 id 로 **옮깁니다.**
   (지우고 새로 만드는 게 아니라 참조만 바꿉니다.)
3. 참조를 다 옮긴 뒤에야 중복 멤버 노드를 지우고, 삭제 기록을 남깁니다.
4. 끝나면 `_meta.migrationVersion` 을 적어 두 번 돌지 않게 합니다.

### 같은 업무가 두 개로 보일 때

제목·담당자·등록일이 모두 같은 항목을 찾되, **내용까지 완전히 같을 때만** 하나로 줄입니다.
진행률이나 보조 업무가 조금이라도 다르면 서로 다른 업무로 보고 **둘 다 그대로 둡니다.**

줄인 항목도 지워 없애지 않고 `duplicateBackup/<시각>` 에 원본 그대로 보관합니다.
판단이 애매해서 남겨 둔 항목도 같은 자리에 함께 복사해 둡니다.

### 팀 데이터 통째로 받아 두기

☁ 배지 → 상태 패널 → **팀 데이터 백업** 을 누르면
`shared/taskTracker` 전체를 JSON 파일로 내려받습니다.

### 충돌은 이렇게 막습니다

전체 데이터를 통째로 덮어쓰지 않습니다. **바뀐 항목만 그 항목의 경로에** 씁니다.

```text
shared/taskTracker/tasks/{프로젝트id}
shared/taskTracker/tasks/{프로젝트id}/subtasks/{보조업무id}
shared/taskTracker/routines/{루틴id}     ... 컬렉션마다 동일
shared/taskTracker/tombstones/…          삭제 기록
```

항목은 언제나 **자기 id 로** 묶습니다. 예전 버전이 배열로 저장해 둔 데이터는
키가 `0,1,2…` 인 배열 인덱스라, 그대로 두면 같은 항목이 두 벌로 보입니다.
접속하면 그 잔재를 찾아 자동으로 정리합니다.

항목마다 `revision` · `updatedAt` · `updatedBy` 가 붙습니다.

- 쓰기는 트랜잭션(SDK) 또는 조건부 PATCH(REST)로 처리하고,
  **원격 revision 이 더 크면 쓰지 않습니다.** 오래된 값이 최신 값을 못 덮습니다.
- 받을 때도 통째로 갈아끼우지 않고 **id 기준으로 한 건씩** 최신인 쪽을 고릅니다.
  보조업무도 한 건씩 비교하므로, 두 사람이 같은 프로젝트에 각자 보조업무를
  추가해도 양쪽 다 남습니다.
- **삭제는 추측하지 않습니다.** "내 화면에 없다" 를 삭제로 보면, 아직 최신
  내용을 못 받은 탭이 남의 항목을 지웁니다. 그래서 실제로 지울 때만 삭제 기록을
  남기고(`tombstones/…`), 그 기록이 있을 때만 지웁니다.
- 모달에서 편집 중인 항목은 원격 값으로 덮지 않고, 창을 닫을 때 반영합니다.
- 같은 브라우저의 여러 탭은 BroadcastChannel(없으면 `storage` 이벤트)로
  즉시 서로 맞춥니다. 탭마다 고유 id 가 있어 자기가 보낸 변경은 다시 받지 않습니다.

### 정보는 사라지지도 겹치지도 않습니다

한 번 기입된 정보가 누락·삭제·중복되지 않도록 코드가 직접 막습니다.

- **중복 차단** — 같은 id 는 언제나 하나로 합칩니다. 저장·불러오기·병합·복구
  어느 경로로 들어와도 이 검사를 지나갑니다.
- **근거 없는 삭제 차단** — 항목이 사라지려는데 "지웠다" 는 기록이 없으면
  자동으로 되살리고, 원격에도 다시 올립니다. 콘솔에 `[보호]` 로 남습니다.
- **자동 백업** — 무언가 줄어들기 직전(실제 삭제·정리·가져오기·전체 초기화)마다
  이 브라우저에 백업을 남깁니다. 최근 12개까지 보관합니다.
- **되돌리기** — 상단 ☁ 배지 → 상태 패널에서 백업 시점을 골라 되돌립니다.
  되돌리기 직전 상태도 한 번 더 백업됩니다.

실제로 지우려면 삭제 버튼 + 확인창을 거쳐야 하고, 그때만 삭제가 반영됩니다.

### 팀원 PC 가 구버전을 물고 있을 때

이 앱은 `index.html` 한 장이라 브라우저가 그 파일을 캐시에 오래 들고 있으면
팀원 화면만 옛 버전으로 남습니다. 그래서 실행 중인 버전을 서로 비교합니다.

- 접속하면 자기 버전을 `shared/taskTracker/_meta` 에 적습니다.
- 나보다 새 버전이 원격에 있으면 **자동으로 한 번 새로고침**합니다.
- 그래도 옛 버전이면 상단에 주황색 띠로 알리고 **새로고침** 버튼과
  `Ctrl+Shift+R` 안내를 띄웁니다.
- 현재 버전은 ☁ 배지 툴팁과 상태 패널의 **버전** 줄에서 볼 수 있습니다.
  내 PC와 팀원 PC의 값이 같은지 바로 비교하면 됩니다.

콘솔(F12)에는 상태가 그대로 찍힙니다.

```text
[TaskTracker] build 2026.08.27-07 · https://…
[TaskTracker] Firebase connected (실시간 리스너) · build 2026.08.27-07
[TaskTracker] Firebase read success
[TaskTracker] Firebase write success (3 path)
[TaskTracker] Firebase write failed: …
```

저장이 실패하면 ☁ 배지가 **저장 실패** 로 바뀝니다. 조용히 넘어가지 않습니다.

> **공개 데이터베이스입니다.** 로그인 없이 누구나 읽고 쓸 수 있는 방식이라
> 주소를 아는 사람은 데이터를 볼 수 있습니다. 민감한 내용은 넣지 마세요.
> 백업이 필요하면 상단 **내보내기** 로 JSON 파일을 받아 두세요.
